# TrafficTracer Complete 1.0.10

Released on 2026-08-26 for Linux x86-64.

## Performance

- Capture preparation no longer repeatedly scans every historical Session.
- Worker startup reuses an output-root-bound persistent Session catalog and
  inspects only indexed recovery candidates.
- Session history is paginated before manifest materialization. The global
  five-tuple search loads all Sessions only after an explicit query.
- Chrome scratch profiles are separated from packet evidence and stored below
  a private application-owned runtime directory.

## Observability and recovery

- The UI displays the active operation plus operation, stage, and total elapsed
  time and restores that progress after route changes.
- Worker recovery and catalog reconciliation timings remain visible in the UI.
- Cold profiles are deleted only after owned Chrome processes quiesce. Warm
  profiles survive normal cleanup and Worker crash recovery.
- Unknown or symlinked profile layouts still fail closed and are never removed.

## Compatibility

TrafficTracer Complete 1.0.10 pins the Worker, Mihomo core, and Clash Verge UI
as one component set. Use the bundled components rather than mixing this Worker
or UI with an older Complete package.

The Debian bundle version is `2.5.2+traffictracer.1.0.10`, so package managers
treat it as newer than 1.0.9 while preserving the existing Clash Verge package
identity and application data directory.

Legacy Sessions remain readable. The persistent catalog is disposable derived
metadata: deleting `.session-catalog/catalog-v1.json` triggers a safe rebuild
from authoritative manifests.

## Upgrade

```bash
cd /path/to/traffictracer-complete-v1.0.10-linux-x86_64
sha256sum -c SHA256SUMS
sudo apt install ./TrafficTracer-Complete_1.0.10_linux_x86_64.deb
```

Building and verifying the package does not stop the running application. Exit
the existing UI normally during a maintenance window before installing or
launching the new version.
