# TrafficTracer Complete 1.0.27

Linux x86-64 validation build on Ubuntu 24.04 LTS.

This release corrects two application-quality decisions found in the
64-target, three-protocol capture. A transient
`net::ERR_CERT_VERIFIER_CHANGED` navigation event no longer overrides a
successful 2xx main document from the same target, frame, and loader. The
intermediate error remains explicit recovery evidence; unrelated iframe or
replacement-loader responses cannot create a false recovery.

Pipeline manifest schema version 9 records each bounded application retry as
an auditable attempt with Session, Batch, protocol, quality, evidence,
analysis-generation, error, and timestamp provenance. The best evidence is
selected monotonically, so a retry that reaches a Chrome error page cannot
replace an earlier completed document. Exact quality ties retain the earlier
attempt. Aggregates count the selected attempt once and expose recovery volume
separately as `attempts_total`.

The TrafficTracer page displays the selected attempt and full retry history.
For terminal historical pipelines, **Reconcile existing analyses** explicitly
refreshes attempt quality from already published analysis generations without
starting Chrome, packet capture, or analysis.

Schema v1-v8 Pipeline manifests remain readable, including an interrupted
schema-v8 retry checkpoint. The Deb bundle version is
`2.5.2+traffictracer.1.0.27`, allowing an in-place upgrade from 1.0.26.
Personal proxy profiles, credentials, browser profiles, captured datasets, and
user configuration are excluded from the packages.

Source validation passed 737 Python tests, 202 Rust library tests, seven Rust
integration tests, 94 frontend tests, 21 Node tests, TypeScript type checking,
ESLint, and the Python/Go/Rust cross-component contract gate. The affected
Hysteria2 v.qq Session was also replayed read-only and classified as a recovered
successful navigation.
