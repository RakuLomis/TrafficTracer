# TrafficTracer Complete 1.0.16

Released on 2026-09-02 for Linux x86-64.

## Added

- Added an opt-in, one-attempt application recovery policy for YAML Capture
  Groups and Profile/node Pipelines.
- Retries only explicit transient playback classifications emitted by analysis.
  Every retry starts a fresh managed Chrome process, Job, and Session.
- Added persistent per-target attempt history and links to prior attempt
  analyses in Capture Group progress.

## Correctness and safety

- The policy is disabled by default and can never exceed one retry per target.
- Positive but short playback, unknown reasons, capture/analysis exceptions,
  proxy protocol failures, interruptions, and cancellations are not retried.
- Pipeline quality uses the effective final Session for each target, so a
  recovered first attempt remains auditable without incorrectly leaving the
  final application plane failed.
- Batch resume preserves the consumed retry budget and all prior Sessions.

## Compatibility

TrafficTracer Complete 1.0.16 keeps Worker API 2, Session manifest 2, and Mihomo
tracing API 1. Job schema advances to 3 for the frozen application retry policy.
Batch manifest advances to 2 for per-target attempt history; schema-v1
manifests are migrated in memory when loaded.

The Debian bundle version is 2.5.2+traffictracer.1.0.16, so package managers
treat it as newer than 1.0.15 while preserving the existing Clash Verge package
identity and application data directory.

## Upgrade

~~~bash
cd /path/to/traffictracer-complete-v1.0.16-linux-x86_64
sha256sum -c SHA256SUMS
sudo apt install ./TrafficTracer-Complete_1.0.16_linux_x86_64.deb
~~~

Exit the currently running UI normally before launching the installed version.
Building and verifying the package does not stop the running application.
