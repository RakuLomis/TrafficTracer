# TrafficTracer Complete 1.0.25

Linux x86-64 stability build on Ubuntu 24.04 LTS.

This release prevents the frozen TrafficTracer Worker environment from leaking
PyInstaller bundle library paths into Chrome, tshark/dumpcap, Mihomo, and
analysis subprocesses. The failure observed in the preceding full capture had
Chrome mapping common libraries from `/tmp/_MEI...` before terminating with
`SIGSEGV`; kernel evidence did not indicate an out-of-memory kill.

Managed Chrome exits and CDP disconnects are now typed, persisted in Session
lifecycle evidence, and eligible for at most one fresh automatic retry when the
default retry option is enabled. Each failed attempt remains auditable. Chrome
stderr is compacted to a maximum 64 KiB per Session.

Application analysis accepts a completed top-level 2xx document as explicit
completion evidence for SPA and long-lived pages even when `loadEventFired` is
absent. Main-document TLS, DNS, timeout, connectivity, and generic network
failures are reported separately. Deterministic TLS certificate errors are not
automatically retried.

Source validation passed 719 Python tests, 22 focused TrafficTracer UI tests,
TypeScript type checking, Rust formatting, and compilation/testing of the
affected Rust command module. Component-lock and packaged-artifact audits are
required before installation.

The Deb bundle version is `2.5.2+traffictracer.1.0.25`, so package managers
recognize it as newer than 1.0.24. Personal proxy profiles, credentials, browser
profiles, captured datasets, and user configuration are excluded from release
artifacts.

See [browser process isolation and quality](../complete/browser-process-isolation-and-quality.md)
for the implementation and validation boundary.
