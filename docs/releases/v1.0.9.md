# TrafficTracer Complete 1.0.9

Released on 2026-08-24 for Linux x86-64.

## Added

- Carrier metadata now records whether protocol and path evidence came from the
  physical carrier lifecycle or a bounded leaf/post-flow fallback.
- Strict protocol capture can target one named proxy selection group.
- The TrafficTracer page restores its environment, target configuration,
  selected targets, recent Job or Capture Group, capture folder, pagination,
  selected Session, and persistent failure details after navigation.

## Fixed

- Capture-tail coverage is part of the PCAP index contract and no longer causes
  a completed capture to fail during artifact validation.
- Sessions failed specifically by analysis or consistency validation can be
  reanalyzed in the same directory with their original raw captures preserved.
- Successful standalone reanalysis repairs the matching Capture Group child.
  A group with remaining targets becomes resumable at the next target; a fully
  repaired group becomes completed.
- Protocol preflight no longer treats unrelated selected groups in a mixed
  configuration as proof that the current capture uses multiple protocols.
- Capture startup and runtime failure information remains visible after route
  changes, while single captures and Capture Groups replace one another as the
  current task.

## Compatibility

The Worker, UI, and Mihomo core are a pinned set. Do not combine the 1.0.9
Worker or UI with an older TrafficTracer core because carrier evidence-source
fields and protocol preflight semantics are interpreted together.

The Debian bundle version is 2.5.2+traffictracer.1.0.9. It upgrades the existing
Clash Verge package identity while preserving its application data directory.

## Upgrade

Verify the package from its release directory:

```bash
cd /path/to/traffictracer-complete-v1.0.9-linux-x86_64
sha256sum -c SHA256SUMS
sudo apt install ./TrafficTracer-Complete_1.0.9_linux_x86_64.deb
```

Building and verifying the package does not stop the running application. Exit
the existing UI normally during a maintenance window before installing or
launching the new version.

If a Session from an earlier run is in `ANALYSIS_FAILED` or
`ANALYSIS_CONSISTENCY_FAILED`, select its timestamp folder and use Analyze
again. Its raw capture remains in place and the owning Capture Group is updated
after analysis completes.
