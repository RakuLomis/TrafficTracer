# TrafficTracer Complete 1.0.20

TrafficTracer Complete 1.0.20 repairs the matrix capture startup failure and
protects unrelated network sessions during multi-Profile experiments.

## Fixed

- Capture-only matrix Jobs now accept `analyze_after_capture: false` when
  Pipeline orchestration provenance is present.
- The Worker exposes a side-effect-free `batch.validate` method. Pipeline
  startup validates every distinct target before changing a Profile, selecting
  a node, creating a Session, or launching Chrome.
- Shared contract and Worker API failures are classified as systemic and stop
  the complete Pipeline immediately, even when per-run failures are otherwise
  allowed to continue.
- Pipeline node transitions no longer call Mihomo's global close-connections
  operation. Existing SSH, remote desktop, and system-proxy connections are
  preserved and the manifest records a read-only connection inventory.
- Pipeline failures are persisted in the TrafficTracer page and remain visible
  after navigating away and returning.
- Linux packaging tests derive their expected artifact version from the product
  version constant instead of a stale hard-coded release.

## Compatibility

Worker API remains version 2, Job schema remains version 3, and Pipeline
manifest schema remains version 7. The added Worker method and
`connectionDrain.state = preserved` value are backward-compatible extensions.
Historical `drained` evidence remains readable.

The Debian bundle version is `2.5.2+traffictracer.1.0.20`.
