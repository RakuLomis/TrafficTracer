# TrafficTracer Complete 1.0.17

Prepared on 2026-09-03 for Linux x86-64.

## Added

- Added 1-20 independent repetitions for every queued `(Profile, selector, node)` candidate.
- Added candidate-major serial execution, exact node × repetition × target estimates, and durable candidate/repetition progress.
- Added `pipeline-aggregate.json` with per-candidate run, Session, capture-integrity, correlation, and application counters.

## Correctness and recovery

- Every repetition owns a distinct run ID, Capture Group checkpoint, and output directory.
- Resume identifies `(candidate_ordinal, repetition_index)`, skips completed repetitions, and resumes only the interrupted inner Capture Group.
- Repetition sampling remains separate from the bounded URL-level application retry policy.
- Completed runs with quality degradation now produce `completed_with_degraded`; actual failed or skipped runs remain `completed_with_errors`.
- Pipeline manifest schema v4 retains schema v1-v3 readability and migrates historical runs as one repetition per candidate.

## Compatibility

TrafficTracer Complete 1.0.17 keeps Worker API 2, Job schema 3, Batch manifest 2, Session manifest 2, and Mihomo tracing API 1. Repetition orchestration is owned by Clash Verge, so the Python Worker Batch contract is unchanged.

The Debian bundle version is `2.5.2+traffictracer.1.0.17`, preserving the existing Clash Verge package identity and application data directory.

## Upgrade

~~~bash
cd /path/to/traffictracer-complete-v1.0.17-linux-x86_64
sha256sum -c SHA256SUMS
sudo apt install ./TrafficTracer-Complete_1.0.17_linux_x86_64.deb
~~~

Exit the currently running UI normally before launching the installed version. Building and verifying the package does not stop the running application.
