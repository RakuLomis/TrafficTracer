# TrafficTracer Complete 1.0.23

Linux x86-64 validation build, prepared on Ubuntu 24.04 LTS.

This update separates whole-pipeline progress from the last sample's quality,
adds scoped correlation evidence, and freezes a verified trace input for new
captures. Resume and ordinary reanalysis reuse that input instead of consuming
a growing journal. Existing capture cutoffs and causal-tail rules are preserved.

**Keep uncompressed trace journal** is optional and enabled by default. When
disabled, the complete journal is losslessly archived only after Linux file
locks confirm all core writers have closed. The original is removed only after
archive verification and manifest publication. Busy writers, unsupported cores
or archival errors retain the original and report pending housekeeping. Explicit
reanalysis retries it. No proxy connections are terminated to force cleanup.

New journal artifacts use recorded/as-of sizes; snapshots and archives use exact
sizes. A read-only dataset review command reports quality eligibility, retry
provenance and artifact discrepancies. Historical data is not automatically
migrated or rewritten. See [implementation and validation](../complete/pipeline-quality-and-trace-sealing.md).

Source validation passed 688 Python tests, 94 frontend tests, 133 Rust
TrafficTracer tests, core/controller tests and the core race detector. Real
capture/Resume acceptance on the new package is still required.

The Deb version is `2.5.2+traffictracer.1.0.23`, higher than 1.0.22. Use a
maintenance window and quit the previous UI normally before starting the new
version. Packages must pass the secret/configuration audit and contain no
personal proxy profiles, credentials, browser profiles or capture datasets.
Local packages are unsigned unless explicitly stated. No GitHub Release upload
is implied by this build.
