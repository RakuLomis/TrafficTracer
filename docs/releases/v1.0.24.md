# TrafficTracer Complete 1.0.24

Linux x86-64 validation build on Ubuntu 24.04 LTS.

Both packet sensors now confirm a complete PCAPNG interface header before
Chrome starts. Job-local monitoring detects unexpected sensor exits. Cleanup
verifies owned Chrome processes have exited before stopping packet capture,
then checks exit results and final PCAPNG block framing. Lifecycle coverage
and packet-drop evidence are separate: unavailable drop counts remain unknown.
Reanalysis cannot turn recorded incomplete capture coverage into a passing
capture-quality result.

New immutable trace snapshots use lossless streaming gzip (level 6). Logical
and stored sizes/hashes are recorded separately, and Resume reuses the same
verified input. Schema version 1 snapshots remain readable without migration.
NetLog, CDP, PCAP, trace cutoff and causal-tail rules are unchanged. The existing
optional original-journal retention/archival policy is unchanged.

Source verification: 702 Python tests and 94 frontend tests passed, along with
TypeScript and targeted lint checks. The new packet lifecycle passed an
isolated zero-packet loopback smoke test. Real TUN/browser and long-batch Resume
acceptance on the installed version remain required.

The Deb version is `2.5.2+traffictracer.1.0.24`, higher than 1.0.23. Packages must
pass component-lock and secret/configuration audits. Personal proxy profiles,
credentials, browser profiles and datasets must not be included. Packages are
unsigned unless stated otherwise; this build does not upload a GitHub Release.

Use a maintenance window to exit the old UI normally before installation and
restart. Building and verifying packages does not require stopping the running
proxy. Do not use an old Worker to analyze schema version 2 gzip snapshots.

See [implementation and verification](../complete/capture-reliability-and-snapshot-compression.md).
