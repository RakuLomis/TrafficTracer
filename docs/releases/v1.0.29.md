# TrafficTracer Complete 1.0.29

Linux x86-64 corrective build on Ubuntu 24.04 LTS.

## Session finalization correctness

The Session v2 contract now accepts the `proxy_semantics` artifact role emitted
by the runtime semantics collector. Successful captures no longer fail while
registering that artifact. Raw artifacts are registered incrementally, so an
unexpected validation failure cannot leave an otherwise failed Session stuck
indefinitely in `capturing` or discard evidence registered earlier.

Profile/node pipelines preserve the actual Batch child error and no longer
collapse this failure into a generic status. Already affected 1.0.28 capture
groups can be inspected and recovered with the narrow, audited
`repair-finalization-failures.py` workflow. Recovered and analyzed Sessions can
then be attached to their original failed attempts with **Reconcile existing
analyses**, without recapture.

## Evidence preservation

Recovery requires clean browser and packet-capture completion, a present Mihomo
trace boundary, valid NetLog/CDP inputs, and capture-time-authoritative runtime
semantics verification. It writes an original-manifest backup and a repair
report but never modifies raw evidence. SS cipher/plugin/mux, VLESS
transport/TLS/REALITY/Vision/mux, Hysteria2 obfuscation, and the supported
semantics for Trojan, VMess, and AnyTLS remain available through the existing
closed allowlist. Credentials, endpoints, node names, and other excluded values
remain excluded.

## Packaging

The Deb bundle version is `2.5.2+traffictracer.1.0.29`, allowing an in-place
upgrade from 1.0.28. The package does not include proxy profiles, credentials,
browser profiles, captures, or local `Yu_VPS` files. Locally built packages are
unsigned unless a Tauri signing key is explicitly provided.
